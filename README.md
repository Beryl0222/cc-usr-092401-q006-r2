# 老红橘保护性收购

广兴镇老红橘接入饮料企业原料链后的收储结算与溯源服务：追踪地块、老树群、
管护记录、采收批次、检验等级、企业交货四条线的连续关系，并在并发与断网
场景下保证「每公斤果实只结算一次、保护树不越界、价格不回溯」。

## 领域模型与连续溯源链

```
农户 ─ 地块 ─ 树群(普通老树/百年保护树)
                │  管护记录（含护树队病害上报）
                ▼
            采收批次（保护树先预占配额）
                │  过磅单（业务摘要幂等：重放返原单/改动转冲突待复核）
                ▼
            检验样本（初检定级、封存留样）
                ▼
            企业交货（锁定交货时适用价规版本）
                ▼
            农户结算（逐磅单计价固化）
                │
   ┌────────────┼─────────────┐
   ▼            ▼             ▼
企业退货     运输损耗      果肉加工路线
（独立流水） （独立流水）    （陈皮等，独立流水）
```

## 强制不变量（由 `domain.py` 校验，测试逐条证明）

1. **同一批果不重复结算**
   - 过磅单对业务关键字段（树群、净重/毛重/皮重、过磅时间、设备号）生成 **SHA-256
     稳定摘要**，按 `(批次, 过磅流水号)` 索引：
     - **重放**：同流水号且摘要完全相同（数值尾零等价，如 `210` 与 `210.0`）→
       返回原磅单并标 `幂等命中`（HTTP 200），不二次入库；交货/结算后离线秤「重启式
       重放」同样识别为重放。
     - **冲突**：同流水号但任一关键字段变化 → HTTP 409 `weigh_conflict`，原磅单原样
       保留，**树群已采重量、预占额度、既有检验一律不动**，另建 `待复核` 磅单冲突
       （双方摘要、差异字段、发现时间、补传人全留痕），接口在响应体 `details` 中
       返回冲突摘要。同一条错误补传反复重推只登记一条冲突。
     - 失败请求（校验不过、超配额等）不产生单据、**不占用流水号**。
   - **复核裁定**只能由合作社/质量复核人执行：`keep` 保留原值（补传作废），或
     `correct` 生成带关联（`更正自/更正为/更正冲突`）的**新更正磅单**：
     - 交货前更正：原单（含原检验）保留为非现行，新单接管重量/树群口径并须重检；
       树群已采重量与预占用量按现行磅单重算，更正后超预占则整笔拒绝且状态还原。
     - 已交货/已结算**不得替换**原单：原单与既有结算链不动，新旧磅单关联并存，
       另出**重量差异调整**（结算时按交货价规折算补付/扣回）。
   - 交货锁定当时现行磅单**快照**，结算只遍历该快照；交货后更正单永不进入第二结算链。
     并发补传与交货、结算交错时，每公斤仍只进入一个结算链，重复结算返回
     `already_settled`。
   - **冲突可见性**：果农只看本人的裁剪冲突摘要（无农户身份号、补传人、付款字段）；
     企业与护树员对冲突接口一律 403。
2. **保护树采收不越界**：百年保护树按采收季下达重量+次数配额；采收前按批次
   预占（跨批次汇总核额），过磅回冲预占，超采当场拒绝；无配额不得采收。
3. **价格不回溯**：合约记录签约时价规版本；交货时锁定当时适用价规，应收金额
   随结算固化。之后市场价涨跌只能发布价规新版本，历史结算分文不改。
4. **复核留痕与价差**：质量复核改级时，原检验记录与封存样本保留（标为非现行），
   新记录标注「复核自」。结算前改级按新等级计价；结算后改级另出**价差调整**
   （补付/扣回），不覆盖原结算行。
5. **四条独立流水**：农户结算 / 企业退货 / 运输损耗 / 果肉加工分账；退货不冲减
   农户应收；数量勾稽 `退货 ≤ 到货 ≤ 交货核定`，加工投入不得超过来源可处置量。
6. **护树队最小权限**：只能上报病害/违规采摘、查看裁剪后的树群视图；结算、
   账本、批次、过磅、磅单冲突、反查一律 403。
7. **成品原料反查**：企业可从交货单或陈皮加工路线反查地块、树群、管护记录、
   历次检测依据（含样本编号）与实际受益农户；只能反查本企业的交货单。

## HTTP 接口

除 `GET /health` 外均需 `X-Actor-Token` 头，JSON 收发；业务错误返回
`{"error": 代码, "message": ..., "details"?: ...}`（401/403/404/409/422）。
`POST /weigh` 用状态码区分三种结果：**201** 新建、**200** 同摘要重放（`幂等命中`）、
**409 `weigh_conflict`** 关键字段冲突（`details` 为待复核冲突摘要）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/actors` | 登记身份令牌（角色：果农/合作社/质量复核人/护树队/收购企业） |
| POST | `/farmers` `/plots` `/trees` | 农户、地块、树群建档 |
| POST | `/quotas` | 保护树按季配额（重量+次数） |
| POST | `/cares` `/reports` | 管护记录；护树队上报病害/违规采摘 |
| POST | `/batches` `/reservations` | 开立采收批次；保护树额度预占 |
| POST | `/weigh` | 过磅（毛重/皮重、断网标记）；201 新建 / 200 重放 / 409 冲突待复核 |
| GET | `/conflicts` `/conflicts/{id}` | 磅单冲突待办（可按 `?状态=待复核` 过滤）；果农只见本人裁剪摘要 |
| POST | `/conflicts/resolve` | 有权限角色裁定：`keep` 保留原值 / `correct` 生成更正磅单或差异调整 |
| POST | `/inspections` `/reviews` | 初检定级封存样本；复核改级 |
| POST | `/price-rules` `/contracts` | 发布不修改的价规版本；签约锁定基准价规 |
| POST | `/deliveries` `/settlements` | 交货锁价并锁定磅单快照；合作社逐磅单结算 |
| POST | `/returns` `/losses` `/processing` | 退货 / 损耗 / 陈皮等加工三条独立流水 |
| GET | `/batches` `/batches/{id}` `/trees/{id}` | 链上查询（按角色裁剪） |
| GET | `/settlements/{id}` | 结算单（含等级价差与重量差异调整） |
| GET | `/ledgers/{农户结算|企业退货|运输损耗|果肉加工}` | 分账导出 |
| GET | `/trace?delivery=…` 或 `?route=…` | 成品原料反查 |

## 运行与测试

```bash
python3 service.py --check     # 基础配置检查
python3 service.py --port 8000 # 启动服务
npm test                       # 54 个用例：契约 + HTTP 集成 + 领域不变量（含并发）
```

## 文件

- `domain.py` — 领域对象、四流水与全部不变量（线程安全，内存存储）。
- `service.py` — HTTP 适配层与路由，不含业务规则。
- `test_domain.py` — 43 个领域用例，含断网重放、并发过磅/结算/申诉、
  磅单摘要冲突与待复核裁定、交货前更正、结算后重量差异调整、
  保护树配额、价差方向、价格不回溯、反查链。
- `test_api.py` — 8 个 HTTP 用例，验证鉴权、错误码、重放(200)/冲突(409)
  区分、冲突裁定权限与端到端流程。
- `service_contract.py` — 健康检查与路由暴露的原始契约。
- `fixtures/domain.json` — 统一领域称谓与不变量清单。
